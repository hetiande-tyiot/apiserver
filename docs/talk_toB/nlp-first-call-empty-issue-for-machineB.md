# 機器A → 機器B：NLP 第一次呼叫回空白問題排查

**日期：2026-05-13**
**發件：機器A（amidaemon_cyberon.py）**
**收件：機器B（sop_api_server / 110LLM）**

---

## 問題描述

在實測中發現，caller 說完第一句話後，110LLM **沒有回傳任何回覆文字**（`outputs: []`），導致系統對使用者沒有任何語音回應。使用者以為系統沒聽到，重複說了同一句話，才在第二次收到 LLM 回覆——且第二次一次回傳了兩句。

## 疑問一：第一次 /call/stt 為何 outputs 為空？

### 呼叫流程（機器A側）

1. 通話建立 → POST `/call/start`（含 session_id）
2. 110LLM 開新 session → TTS 合成開場白 → 播給 caller
3. Caller 說完第一句 → POST `/call/stt` `{"uuid":..., "text":"你好，我要報案。", "role":"caller"}`
4. 機器A等待機器B回傳 `outputs`，但收到空陣列

### 請機器B確認

- `/call/stt` 第一次收到 caller 輸入時，110LLM `/session/{id}/input` 的 HTTP 回應內容為何？
  - `outputs` 是否確實為 `[]`？
  - `done`、`error` 欄位值？
- 110LLM session 在開場白 TTS 之後是否需要「額外一個 turn」才會進入可接收 caller 輸入的狀態？
- 是否有 rate limiting 或 session warm-up 導致第一次輸入被忽略？
- 機器B的 log 在第一次 `/call/stt` 呼叫時有無任何錯誤或警告？

---

## 疑問二：第二次 /call/stt 為何一次回兩句？

### 觀察

第二次送同一句話（`你好，我要報案。`），110LLM 在同一次回覆中回傳了兩個 output：

```json
{
  "outputs": [
    "請問您現在需要的是哪一類協助：找人、找物，還是環境求助？",
    "為了協助分案，請直接告訴我：您要找人、找物，還是環境求助？"
  ]
}
```

### 請機器B確認

- 110LLM 是否在 session 內部累積了第一次（未回應的）輸入，第二次觸發時一起回覆？
- 還是這是 LLM 本身的輸出行為（單次產生多句回覆）？
- 若是累積，機器B可否在第一次就正確回應，避免累積？
- 若是 LLM 多句輸出的正常行為，機器B是否建議機器A只取最後一句或合併處理？

## 疑問三：TTS 播放期間 /call/stt 的處理方式

機器A目前在 TTS 播放期間（`STATE_SPEAKING`）會忽略所有 STT 輸入，不送 NLP。  
**請確認**：機器B的 `/call/stt` endpoint 是否有類似的狀態保護，或是否完全依賴機器A來控制送入時機？
